# Do we need a stored balance column?

## Question

The stocktake screen lists 400 lots. Is deriving every balance from the ledger
fast enough, or does the screen need a stored balance?

## What we know

- REQ-002 says a balance is derived from the ledger and no stored balance is a
  source of truth.
- The ledger is append-only (REQ-001), so a stored balance can only ever be a
  cache, never a fact.
- The stocktake runs once a week, over 400 lots, on the same database.

## Options

1. **Derive every balance.** One indexed aggregate per lot. The screen is
   correct by construction and there is no invalidation rule to get wrong.
2. **Cache the balance in the lot row.** Faster reads, and a cache that can
   disagree with the ledger. Every write path has to remember to update it.

## Recommendation

Option 1. 400 lots is an index problem, not an architecture problem. This is
wrong only if the aggregate cannot be indexed on `(warehouse_id, lot_id)` —
measure that before choosing option 2.
