# Where does dedupe belong: webhook receiver or ledger?

## Question

The provider delivers at least once. Do we dedupe in the HTTP receiver, in the
ledger, or both?

## What we know

- REQ-001 says an event is applied exactly once, and REQ-004 says every state
  change records the idempotency key that caused it.
- The provider retries with the same event id for up to 72 hours.
- A receiver that dedupes in memory loses the record on a restart, which is
  exactly when a retry arrives.

## Options

1. **Dedupe in the ledger.** A unique index on `(provider, event_id)`. The
   receiver may be hit twice; the second insert loses to the index and the
   handler returns 200.
2. **Dedupe in the receiver with a cache.** Faster, and a cache that is lost
   on restart re-applies the event.
3. **Both.** The cache is an optimisation; the index is the rule.

## Recommendation

Option 1, which is option 3 without the cache until a measurement asks for it.
Adding the cache later is a performance change; removing it after it has hidden
a bug is a debugging session.

## Open questions

None that block the design.
